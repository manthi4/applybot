## Summary

Replaces the Vertex AI–specific LLM client with a provider-agnostic client backed by [litellm](https://github.com/BerriAI/litellm), making provider/model selection a config change instead of a code change. LLM provider keys and the default model are now **mutable at runtime** (GCP Secret Manager + Firestore), laying the groundwork for bring-your-own-key: users will be able to supply their own API key and switch models without a redeploy. Also reworks the dashboard's resume-parsing flow to use the new client.

## LLM engine rewrite (`src/applybot/llm/`)

**Before:** abstract `LLMClient` hierarchy (`GeminiClient` via the Vertex AI `google-genai` SDK, `AnthropicClient`), a `get_llm()` factory driven by a pydantic-settings `config.py`, and a `fast`/`smart` tier system with per-provider model env vars (`GEMINI_MODEL_FAST`, `ANTHROPIC_MODEL_SMART`, `VERTEX_REGION`, ...).

**After:** a single module-level `complete()` function:

- Provider is inferred from the model-string prefix (litellm convention: `gpt-*`, `claude-*`, `gemini/*`); one default model replaces the fast/smart tiers; structured output via `output_type=SomePydanticModel`.
- New module layout:
  - `providers.py` — `LLMProvider` enum + per-provider metadata (env var, secret id, prefixes); adding a provider is a one-place edit
  - `_backends.py` — GCP I/O shims (Secret Manager, Firestore)
  - `client.py` — TTL caches, runtime-mutable stores, `complete()`
- **Runtime-mutable config:** keys live one-per-provider in Secret Manager; the default model lives in a Firestore `config/llm` doc. Both are read through a ~30 s in-process TTL cache so every service picks up `update_provider()` / `set_default_model()` changes within seconds — no redeploy, and no dependence on `secret_key_ref` env vars (which only resolve at instance cold-start).
- New env surface: `LLM_MODEL_DEFAULT`, `LLM_MAX_RETRIES`, `GCP_PROJECT_ID`, plus per-provider key env vars (`OPENAI_API_KEY` / `ANTHROPIC_API_KEY` / `GEMINI_API_KEY`). Outside GCP (`GCP_PROJECT_ID` unset) the module runs env-only — local dev and tests need no Google Cloud.
- litellm receives the resolved `api_key` explicitly on every call (no global litellm state).

## Call-site migration

`application/question_answerer.py`, `application/resume_tailor.py`, `discovery/{query_builder,ranker,enricher}.py`: `get_llm().structured_output(prompt, Model, tier="smart")` → `complete(None, None, prompt, output_type=Model)`. Client and discovery unit tests updated (mocked, offline).

## Dashboard resume parsing

- Deleted `services/resume.py` (359 lines of old parsing); trimmed `resume_storage.py` to pure GCS storage; renamed `enrichment.py` → `resume_to_profile.py`
- New flow: extract raw text from `.md` / `.docx` / `.pdf` (text-based only) → one `complete()` call produces the updated `UserProfile`
- `pages/profile.py` wires upload → storage → enrichment

## Infra

- One Secret Manager secret per provider (`openai-api-key`, `anthropic-api-key`, `gemini-api-key`) replaces the single `llm-api-key`
- Dropped `LLM_MODEL_FAST`/`LLM_MODEL_SMART` and key env-var injection from Cloud Run and the discovery Cloud Function; `GCP_PROJECT_ID` remains so the store layer is active
- IAM: per-secret scoped `secretAccessor` (read) + `secretVersionAdder` (write — enables runtime key rotation) instead of the project-wide accessor role

## Follow-ups (not in this PR)

- Dashboard admin endpoints calling `update_provider` / `delete_provider` / `set_default_model` behind the existing TOTP auth (the actual bring-your-own-key UI)
- A fresh deploy needs one `set_default_model()` call before completions work — the default model is intentionally not Terraform-provisioned (Firestore is the source of truth)
- Pre-existing on main: `discovery/orchestrator.py` and `discovery/ranker.py` still import the removed `applybot.config` module
